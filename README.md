# P.S.D v3.5.3 — 内部検索は未実装

[アプリ](https://masaotokumoto12-ux.github.io/PlayerSearch-DBD/) / [共有版](https://dbd-player-search.m-aa-k-one-for-all-a.chatgpt.site)

正本は [CANONICAL.md](./CANONICAL.md)。
P.S.Dの目的は、DBDプレイヤーを内部で検索し、発見した候補アカウントを画面に表示すること。
検索エンジン・サービス内検索へのリンクだけでは達成しない。
現行の共有APIは検索先URLを生成する旧契約であり、この目的は未達。

v3.5.3では「検索を広げる」を削除した。
旧APIの検索画面URLや入力から生成したプロフィールURLは、結果のアカウントリンクとして出力しない。
検索操作では現在「候補アカウントは未取得」と表示する。
これはアカウントが存在しないという判定ではない。
候補取得・実在確認・DBDの根拠・本人一致の確認は、今回実装したとは扱わない。
表示を隠すだけで内部検索が完成したとも扱わない。

## 保持している機能

最大4入力。Steam・X・YouTube・Twitch・TikTok・5chの旧6経路の通信契約を維持する。
旧URLキャッシュは10分、同一操作の重複名は送信前にまとめる。
新規API送信は2秒間隔。429時は1時間、403時は6時間停止し、長いRetry-Afterを優先する。
自動再試行、復帰・履歴閲覧時の検索送信は行わない。
旧経路の保存・再利用は、候補検索結果の保存を意味しない。

履歴は端末内の日別ファイルへ自動保存する。
日付をタップすると、その日の検索履歴を確認できる。
同日・同名を1行にまとめ、2回目以降は「2回目の検索」のように表示する。
閲覧・再読込・再保存・拒否された操作では加算しない。
受け付けたキャッシュ使用の再検索は加算し、翌日は1回から数える。
入力・全体バックアップはpsd-core-v4互換を維持し、過去の日別履歴と回数を含む。
有料API、追加課金、追加クレジットは導入しない。
検索サーバーのソースと管理鍵は公開GitHubへ置かない。

## 検証と未解決事項

```sh
node scripts/check.mjs
node --test tests/client-flow.test.mjs
node scripts/audit-search.mjs
```

`check` は版番号・アセット・公開物等を確認する。
`client-flow` は公開するルートのapp.jsをNodeの模擬画面で実行する。
検索リンクを候補として出さないこと、通信抑制、日別履歴、回数、復元を検証する。
実ブラウザー、実IndexedDB、外部媒体の検索結果の検証とは区別する。

`audit-search` は通常4入力・1 POSTで旧APIのURL生成・順序・CORSだけを確認する。
`contractStatus: passed` と `purposeStatus: unmet` を分け、目的未達の終了コードは1とする。
通信できない、または利用制限で検証を完了できない場合は終了コード2とする。
`--full` でもPOST間は最低2秒あけ、403・429で再試行しない。
スクリプト自身は外部媒体への検索を送信しない。サーバー内部の通信件数は未計測。

監査・修正範囲と実行結果は [2026-10-27の監査](./AUDIT_2026-10-27.md) を参照。
P0はサーバー側の候補取得とDBD根拠の取得、取得状態の区別。
その実装と外部結果の検証が終わるまでは、検索機能完成と判定しない。
